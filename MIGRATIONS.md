# Миграции базы данных

## Зачем это нужно

Схема базы создаётся вызовом `Base.metadata.create_all()` в `init_db()`.
У него есть важное ограничение: **он умеет только создавать новые таблицы**.

Если в существующую таблицу добавить колонку, `create_all()` молча ничего не
сделает. Код будет ждать колонку, база её не вернёт, бот упадёт с
`OperationalError: no such column`. На боевой базе с живыми данными
варианта «удалить файл базы и пересоздать» уже нет.

Alembic решает именно это: описывает изменение схемы отдельным файлом и
применяет его к базе без потери данных.

## Разовая настройка

### Если база уже существует (боевая или ваша локальная)

Отмечаем, что база уже соответствует базовой ревизии:

```bash
alembic stamp 0001_baseline
```

Команда ничего не меняет в таблицах — она лишь записывает номер ревизии
в служебную таблицу `alembic_version`.

### Если база создаётся с нуля

```bash
python init_db.py        # create_all() создаст таблицы
alembic stamp head       # отмечаем актуальное состояние
```

## Как менять схему дальше

1. Правим модели в `database/models.py`.
2. Генерируем миграцию:

   ```bash
   alembic revision --autogenerate -m "добавил колонку X"
   ```

3. **Обязательно читаем сгенерированный файл** в `alembic/versions/`.
   Автогенерация часто промахивается с переименованиями (видит их как
   «udalitь старую колонку + создать новую», что теряет данные).
4. Применяем:

   ```bash
   alembic upgrade head
   ```

Вернуться на шаг назад: `alembic downgrade -1`.
Посмотреть текущую ревизию: `alembic current`.
История: `alembic history`.

## Добавление колонки с данными

Если колонка `NOT NULL`, её нельзя добавить в таблицу с данными одним
движением. Порядок такой:

```python
def upgrade() -> None:
    # 1. добавляем как nullable
    op.add_column("users", sa.Column("language", sa.String(), nullable=True))

    # 2. засыпаем значения старым строкам
    op.execute("UPDATE users SET language = 'ru' WHERE language IS NULL")

    # 3. теперь можно запретить NULL
    with op.batch_alter_table("users") as batch_op:
        batch_op.alter_column("language", nullable=False)
```

`batch_alter_table` обязателен для SQLite: он не умеет `ALTER COLUMN` и
`DROP COLUMN` напрямую. Alembic в этом режиме пересобирает таблицу через
временную и переносит данные. В `env.py` уже включён `render_as_batch=True`,
поэтому автогенерация сразу пишет код в batch-виде.

## Перед применением на боевой базе

1. Остановить бота и веб-сервер.
2. Сделать копию файла базы: `cp bot.db bot.db.backup-$(date +%F)`.
3. `alembic upgrade head`.
4. Запустить обратно и проверить `/start` и `/pet`.

Копия базы — не формальность. Откат миграции восстанавливает структуру,
но не возвращает удалённые значения.
