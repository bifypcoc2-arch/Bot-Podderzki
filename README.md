# Telegram Bot поддержки с модулем «Питомцы»

Telegram-бот с анонимной службой поддержки на базе форум-топиков, ролевым доступом и мини-приложением для ухода за виртуальным питомцем.

## Основные возможности

### Часть 1: Бот поддержки
- Отдельная тема в форуме на каждое обращение
- Полная анонимность в обе стороны: администраторы видят пользователя как короткий код, пользователь видит только бота
- Иерархическая система ролей (5 уровней доступа)
- Режим SPEC для ограничения доступа к теме
- Закрытие обращений командой `/close`
- Баны и статистика сообщений
- Система рассылок с сохранением прогресса
- Очередь ожидания с предложением сыграть

### Часть 2: Модерация рабочей группы
- Муты с произвольным сроком и снятие ограничений
- Исключение из группы
- Предупреждения с автоматическим мутом на сутки при трёх активных
- Топ актива и сводка по группе
- Защита от применения к себе и к админам равного или более высокого уровня

### Часть 3: Модуль «Питомцы»
- 7 видов питомцев
- 5 стадий роста
- 6 параметров ухода
- 5 действий по уходу
- 3 мини-игры
- Магазин с предметами
- 18 достижений
- Система статистики

## Установка

1. **Клонируйте репозиторий**

2. **Создайте виртуальное окружение**
```bash
python -m venv venv
source venv/bin/activate  # Linux/Mac
venv\Scripts\activate     # Windows
```

3. **Установите зависимости**
```bash
pip install -r requirements.txt
```

4. **Настройте конфигурацию**
```bash
cp .env.example .env
```

Обязательные переменные в `.env`:
```env
BOT_TOKEN=ваш_токен_бота
DATABASE_URL=sqlite+aiosqlite:///./bot.db
FORUM_GROUP_ID=id_группы_с_форумом
MINI_APP_URL=https://ваш-домен.com/miniapp
```

Остальные переменные и значения по умолчанию — в `.env.example`.

5. **Инициализируйте базу данных**
```bash
python init_db.py
alembic stamp head
```

Вторая команда отмечает текущую версию схемы, чтобы будущие миграции применялись корректно. Подробности — в `MIGRATIONS.md`.

6. **Добавьте первого администратора**
```bash
python add_admin.py <ваш_telegram_id> OWNER 5
```

7. **Выдайте боту права в рабочей группе**

Бот должен быть администратором группы с правами «Управление темами» и «Блокировка участников». Без второго права команды `/mute` и `/kick` будут отвечать ошибкой.

## Запуск

Бот и веб-сервер — два отдельных процесса, запускать нужно оба.

```bash
python main.py        # бот
python web_server.py  # API мини-приложения
```

## Роли и права

| Роль | Уровень | Права |
|------|---------|-------|
| ADMIN | 1 | Ответы в темах, закрытие обращений, просмотр актива |
| SPEC_ADMIN | 2 | + Доступ к SPEC-темам |
| SENIOR_ADMIN | 3 | + Перевод тем в режим SPEC, муты и предупреждения |
| TECH_ADMIN | 4 | + Рассылки, исключение из группы |
| CO_OWNER | 5 | + Баны и статистика |
| OWNER | 5 | Полный доступ |

Проверка везде идёт по числовому уровню (`role_level >= требуемый`), а не по названию роли. CO_OWNER и OWNER имеют одинаковый уровень 5 и по правам не различаются.

## Команды бота

### Для пользователей
- `/start` — начало работы с ботом
- `/pet` — открыть мини-приложение с питомцем

### Работа с обращениями
- `/close` — закрыть обращение (от уровня 1)
- `/spec`, `/unspec` — управление режимом SPEC (от уровня 3)
- `/ad` — создать рассылку (от уровня 4)
- `/ads` — управление рассылками (от уровня 4)
- `/ban`, `/unban`, `/bans` — блокировки обратившихся (от уровня 5)
- `/stats` — статистика сообщений (от уровня 5)

### Модерация рабочей группы

Работают только внутри группы из `FORUM_GROUP_ID` и касаются её участников, а не обратившихся в поддержку.

- `/mute [цель] [срок] [причина]` — запретить писать (от уровня 3)
- `/unmute [цель]` — снять ограничение (от уровня 3)
- `/warn [цель] [причина]` — вынести предупреждение (от уровня 3)
- `/unwarn [цель]` — снять последнее предупреждение (от уровня 3)
- `/kick [цель] [причина]` — исключить из группы (от уровня 4)
- `/warns` — список активных предупреждений (от уровня 1)
- `/top` — топ актива группы (от уровня 1)
- `/chatstat` — сводка по группе (от уровня 1)

Цель указывается одним из трёх способов: ответом на сообщение человека, через `@username` или числовым ID. Поиск по юзернейму работает только для тех, кто уже писал в группе.

Срок мута пишется как `30m`, `2h`, `1d`, `1w` или русскими буквами (`30м`, `2ч`, `1д`). Голое число — это минуты. Без указания срока мут даётся на час.

Три активных предупреждения дают автоматический мут на сутки, после чего счётчик обнуляется.

### Чем `/kick` отличается от `/ban`

Это разные механизмы для разных людей:

- `/ban` закрывает доступ к поддержке тому, кто пишет боту. Запись ложится в `bans`, человек получает уведомление и больше не может создавать обращения.
- `/kick` и `/mute` касаются участников рабочей группы и работают средствами Telegram.

Внутри темы обращения все сообщения пользователя отправлены самим ботом, поэтому `/mute` в ответ на них не сработает — бот подскажет использовать `/ban`.

## Анонимность

- Сообщения копируются в тему, а не пересылаются: администраторы не видят имя и юзернейм пользователя
- Тема называется коротким кодом — хэшем от ID пользователя
- Ответы администраторов приходят пользователю от имени бота, без подписи
- Связь кода с реальным ID хранится только в базе данных

Модерация группы анонимности не нарушает: в `/top` и `/warns` попадают только участники рабочей группы, а обратившиеся в поддержку в неё не входят.

## Разработка

### Структура базы данных

- `users` — пользователи бота
- `admins` — роли администраторов
- `admin_logs` — журнал действий администраторов
- `admin_stats` — счётчики ответов администраторов
- `chat_activity` — актив участников в рабочей группе
- `bans` — блокировки обратившихся
- `warns` — предупреждения участникам группы
- `topics` — темы поддержки
- `broadcasts` — рассылки
- `user_pets` — питомцы пользователей
- `shop_items` — товары в магазине
- `inventory` — инвентарь пользователей
- `achievements`, `user_achievements` — достижения
- `stats` — статистика пользователей

### API endpoints

Все запросы к `/api/` требуют заголовок `X-Telegram-Init-Data` с подписанными данными Telegram. Идентификатор пользователя берётся из подписи, а не из параметров запроса.

- `GET /api/pet` — состояние питомца
- `POST /api/action` — действие с питомцем
- `GET /api/stats` — статистика
- `GET /api/inventory` — инвентарь
- `GET /api/shop` — список товаров
- `POST /api/shop/buy` — купить предмет
- `POST /api/shop/use` — использовать предмет
- `POST /api/shop/equip` — надеть предмет
- `POST /api/game/phantom-cube` — мини-игра
- `POST /api/game/number-whisper` — мини-игра
- `POST /api/game/cursed-riddle` — мини-игра
- `GET /api/achievements` — список достижений
- `GET /api/achievements/check` — проверить новые достижения
